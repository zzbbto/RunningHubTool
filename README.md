# RunningHub 复制/粘贴应用参数 + 双站同名覆盖迁移（浏览器插件）

在 RunningHub 发布 AI 应用时，即使新应用是**复制**旧应用而来，节点参数也不会自动带过来，每次都要重新选节点 id、改名——因为复制应用**节点 id（nodeId）不变，变的只是 `webappId`**。

这个插件解决两个问题：
1. **复制/粘贴参数**：在来源应用页面点「**① 复制本页参数**」（写入系统剪贴板），到发布页面点「**② 粘贴到本页**」，参数自动填好。
2. **双站同名覆盖迁移**：在 `wallet-migrate` 页面，用源站数据覆盖目标站**同名**工作流/AI 应用（保留目标 id），不同名则新建。双向 `.cn ↔ .ai`。

支持两个域名（两站参数互通）：`www.runninghub.cn` 和 `www.runninghub.ai`

> ⚠️ **安全设计**：复制/粘贴**只读取、只填充表单，不自动发布**。迁移功能**只覆盖数据、不删除资产**，执行前需确认。

## 安装（Chrome / Edge）

1. 下载或克隆本目录（`browser-extension/`）。
2. 打开浏览器扩展页：
   - Chrome：地址栏输入 `chrome://extensions`
   - Edge：地址栏输入 `edge://extensions`
3. 右上角打开 **开发者模式**。
4. 点击 **加载已解压的扩展程序**，选择 `browser-extension/` 目录。
5. 扩展图标出现即安装成功。**请保持已登录 RunningHub**（插件复用你当前登录会话）。

## 使用（点两次按钮）

> 按钮只在**发布/编辑页面**（`/publish/...`）和 **AI 应用界面**（`/ai-detail/...`、`/ai-application`、`/ai-apps`）显示，其他页面（含 `/workflow/:id` 详情/运行页）不会出现，不会打扰正常浏览。
>
> 按钮按页面类型区分：**AI 应用界面**（`/ai-detail/...`，来源页）只显示「① 复制本页参数」；**发布/编辑页面**（`/publish/...`，目标页）只显示「② 粘贴到本页」。互不混淆。
>
> ⚠️ RunningHub 有两种 id：**发布页 `/publish/:id` 的 id 是「工作流 ID」**，**AI 应用界面 `/ai-detail/:id` 的 id 是「应用 ID」**。插件会自动识别当前页面是哪一种，无需你区分。

1. 打开**来源应用**页面（比如 `https://www.runninghub.cn/ai-detail/<来源应用ID>`，或你编辑旧应用的地方）。
2. 点页面右下角的 **📋** 按钮 → 点 **① 复制本页参数**。插件会读取本页应用的全部节点参数并暂存。
3. 打开要发布的**新应用编辑页**（`https://www.runninghub.cn/publish/<新应用ID>`）。
4. 点 **📋** → 点 **② 粘贴到本页**。插件把每个节点的参数填入对应输入框：
   - 文本 / 数字 / 多行文本：直接填入。
   - 下拉选项：按值匹配选择（若目标下拉里没有该选项会提示）。
   - 图片 / 音频 / 视频 / 文件节点：**需手动上传**（浏览器安全限制，无法程序化赋值），面板会标注出来。
5. 核对表单（必要时改名称），然后**手动点击发布**。

> 面板里的 **🔍 诊断本页节点结构** 按钮会把当前页面识别到的节点输入框、nodeId 映射、容器情况列出来。如果复制/粘贴对不上，把这个诊断结果发给我，我可以针对性调整匹配逻辑。

> `.cn` 和 `.ai` 复制的参数都存在浏览器本地（页面 `localStorage`），**跨域名粘贴也通用**——在 `.cn` 复制，到 `.ai` 粘贴一样有效。

## 双站同名覆盖迁移（wallet-migrate 页面）

官方迁移工具只支持「新建」，每次迁移都在目标站创建新资产。本插件的迁移面板支持**同名覆盖**：

1. 打开 `https://www.runninghub.cn/wallet-migrate`（**两个站都要已登录**；`.ai` 需 Google 登录，且需在 `.ai` 站打开过一次页面让插件记录 token）。
2. 点右下角 **🔄** 按钮打开迁移面板。
3. 选**迁移方向**（CN → AI / AI → CN）和**类型**（工作流 / AI 应用）。
4. 选**匹配方式**：
   - **按迁移记录 id**（默认）：读迁移记录 `sourceAssetId→targetAssetId` 精确匹配，已迁移过的资产覆盖其对应目标（最准，不依赖名字）
   - **按名字**：目标站有同名资产则覆盖，否则新建
5. 点 **① 检测同名匹配**：弹出**大结果窗口**，带**页签（工作流 / AI 应用）**，每项可**勾选**（默认全选），顶部显示已选数量。
6. 勾选要迁移的资产 → 点 **执行所选**（确认后）：覆盖用源站数据（**保留目标 id**，海报/标签保留目标站的），新增走官方迁移。

> ⚠️ 覆盖会真实修改目标站数据（名称、描述、节点参数），**不删除资产**。请先在弹窗中核对勾选项，确认无误再执行。

### 工具栏图标

点击扩展图标可：快速打开 `.cn` / `.ai` 首页、查看上次复制的参数列表。

## 工作原理

| 环节 | 实现 |
| --- | --- |
| 复制来源参数 | 复制**全部输入节点**（含文件/图片/视频上传类），带 **id、key（nodeId-fieldName）、显示名（description）**；AI 应用页（`/ai-detail/...`）用 detail 接口取 `nodeInfos`（与页面渲染用同一个接口/字段）；发布/工作流页优先抓页面表单 |
| 参数暂存 | 写入**系统剪贴板**（JSON），页面 `localStorage` 作兜底 —— 同一标签页内导航不丢，无需开两个窗口 |
| 粘贴到本页 | 从剪贴板读取 → 自动打开发布页「选择节点参数」弹窗 → **全覆盖**：移除发布页原有节点，再逐节点按 `key`/`nodeId` 点「添加」→ **值沿用工作流默认值（不填写）**，仅把 id/key/显示名（description）同步为来源 |
| 双站同名覆盖 | 读两站资产列表（`/uc/ai-migration/summary/*`）→ 按名字匹配 → 同名用源站数据调 `/api/webapp/publish` / `/api/workflow/publish` 覆盖（保留目标 id，海报/tags 保留目标站的）；不同名走官方 `/uc/ai-migration/assets` 新建 |
| 保存 | 复制/粘贴**不自动发布**；迁移为写操作但**不删除资产**，执行前需确认 |

```

├── manifest.json   # MV3 配置：host 权限（.cn + .ai）、cookies、background、content_scripts

```

## 常见问题

- **复制失败：WEBAPP_NOT_EXISTS / USER_DOES_NOT_EXIST** → 该应用不存在、你没有权限，或未登录 RunningHub。
- **📋 按钮不出现** → 按钮只在发布/编辑页（`/publish/...`）和 AI 应用界面（`/ai-detail/...`、`/ai-application`、`/ai-apps`）显示；首页、`/workflow/:id` 详情页等不会显示，这是刻意为之。
- **点了「粘贴」提示"还没有可粘贴的参数"** → 说明本页还没复制过，请先到来源应用页面点「① 复制本页参数」，再回来点「② 粘贴到本页」。
- **粘贴后页面值没变** → 部分自定义下拉/组件框架更新方式特殊，请用浏览器 F12 手动确认该控件；或刷新后重试。
- **图片/文件节点** → 浏览器不允许脚本设置 `<input type=file>`，需要手动上传；面板会列出这些节点提醒你。
